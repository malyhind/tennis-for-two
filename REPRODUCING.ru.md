# Повторение работы прибора

## Запуск и проверки

Готовая пара JS/WASM запускается через HTTP. Проверки CLI выполнены с Node.js 24.22.1. Команды перечислены в package.json:

| Команда | Область |
| --- | --- |
| `npm test` | Вычислитель мяча и необязательное native-сравнение |
| `npm run test:display` | Отдельный транзисторный переключатель |
| `npm run test:cpu` | Операторы и входы схемы |
| `npm run test:joint` | Общая схема, луч и перенос состояния |
| `npm run test:worker` | Производственный Worker и переносы по памяти |
| `npm run test:continuity` | Время фронтов около переноса |
| `npm run test:joint-native` | Сравнение native/WASM с холодного старта |
| `npm run test:joint-warm` | Продолжение native/WASM из общей точки |
| `npm run test:mechanics` | Механика ручек и кнопок |
| `npm run test:mechanics-joint` | Механика и электрические входы |
| `npm run test:restart-inputs` | Сохранение входов при переносе |
| `npm run test:controller-worker` | CPU и пульты над производственным Worker |
| `npm run test:transactional-worker` | Восстановление после отказа кандидата |
| `npm run test:glass` | Снеллиус/Френель и сохранение люминофора |
| `npm run test:demo` | Синтетические проверки часов и цикла; после записи — сама запись |

После запуска HTTP-сервера откройте `tests/scope-check.html` для браузерного стенда экрана. Отсутствующие возможности GPU помечаются SKIP. Этот стенд позволяет выполнить аппаратную проверку на своей машине.

Тесты обновляют отдельные JSON в `app/docs/` и создают данные в `tests/results/`. Приложенные исходные отчёты сохраняют даты и область измерений. Для native-сравнений нужен ngspice 45.2; путь задаётся как `NGSPICE=/путь/к/ngspice`. У холодного старта известны расхождения на фронтах и выбор начальной ветви; неуспешный строгий поточечный критерий сохранён. Продолжение из общей точки — отдельная проверка. Пороги и исключаемые окна описаны в исследовании.

## Пересборка WASM

SHA-256 готового `app/vendor/spice.wasm`:
`7e92084ce97153e5288919cfcd64a2255dad37a7e5d9abf2d1350f09df667a5c`.

Нужны Python 3.12+, patch, make и активированный Emscripten. В приложенном протоколе указан Emscripten 3.1.6 и выбранные флаги O3 с подготовленным вычислителем. Подготовку исходников можно проверить отдельно:

```sh
python3 tools/build_solver.py --prepare-only
python3 tools/build_solver.py --optimization O3 --no-lto --evaluator prepared
```

Каждый запуск использует новую папку в `.solver-build/`. Полная сборка печатает путь к результату: `spice.js`, `spice.wasm` и `build.json`. Готовая пара заменяется вместе после сравнения численных проверок. Скрипт проверяет хеши исходных архивов, применяет кумулятивный патч eval2 и использует сохранённую оболочку EEcircuit. Версии инструментов и флаги находятся в `app/vendor/source/`; другой компилятор может изменить байты результата.

## Модель и необязательная запись

Три игровых режима используют одну электрическую модель. Схемы находятся в `app/tennis.cir`, `app/display-switch.cir` и `app/scope.cir`; `app/joint-circuit.js` строит общий deck. `app/joint.cir` — сохранённый вариант для чтения.

`node tools/record-demo.mjs` создаёт необязательную 30-секундную запись через производственный Worker, профили CPU, механику Planck и кодек binary64 без потерь. После записи обновите страницу. Упаковщик исходников исключает созданную запись и формирует манифест её отсутствия; по умолчанию работает живой расчёт.

`python3 tools/study_supply_divider.py` повторяет отдельно описанный статический расчёт делителя питания. Датированные отчёты и исследование разделяют воспроизводимость модели, параметры реконструкции и исторические данные.
